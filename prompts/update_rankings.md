# Задача: обновить рейтинг и очки (приоритет 3)

Ты обновляешь данные теннисного приложения. Работаешь ТОЛЬКО с файлом
`data/rankings.json`. Профили игроков (`data/players.json`) НЕ трогаешь —
там нет рейтинга и очков, они вынесены сюда специально.

## Источник
В ростере два тура. Тур записи — поле `tour` (`"wta"`; нет поля — ATP); он совпадает
с полом игрока в `data/players.json` (`"gender": "f"` — WTA).
- ATP-записи: ATP (atptour.com/rankings) — официальный рейтинг (пересчитывается по
  понедельникам) и набранные очки. Tennis Abstract — для сверки.
- WTA-записи: WTA (wtatennis.com/rankings/singles) — одиночный рейтинг, тоже по понедельникам.
  Игрока узнавай по `wtaId` из `data/players.json` (это id в адресе его страницы на wtatennis.com).

## Что сделать
1. Прочитай `data/rankings.json` (массив записей по playerId).
2. Для каждого игрока обнови (по рейтингу ЕГО тура):
   - `current` — текущая позиция в рейтинге ATP или WTA;
   - `seasonDelta` — изменение позиции за сезон (целое, может быть отрицательным);
   - `trend` — одно из "up" / "down" / "stable" (динамика за последние недели);
   - `ytdPoints` — очки за текущий год (Year-To-Date);
   - `seasonPoints` — очки сезона по твоей текущей методике (как в существующих данных).
   У WTA-записей поля `seasonDelta` и `seasonPoints` могут отсутствовать — добавляй их,
   только если число взято с WTA (Race to the WTA Finals, рейтинг на начало сезона), иначе
   поля не создавай. Поле `tour` не меняй и не удаляй.
3. Не добавляй и не удаляй игроков — состав игроков меняется в `players.json`
   отдельной задачей. Здесь только цифры по уже существующим playerId.

## Правила
- `trend` строго из трёх значений: up / down / stable.
- Не выдумывай числа — бери с ATP / WTA. Не уверен — оставь прежнее значение.
- Никогда не подставляй ATP-рейтинг WTA-игроку и наоборот.
- JSON валидный, UTF-8, отступ 2 пробела.

`python3 build_config.py --check` — и если ок, остановись.
